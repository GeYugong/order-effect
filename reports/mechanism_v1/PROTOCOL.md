# 顺序效应：机制筛查方案 v1

本方案在新增模型调用前固定，冻结时间、源记忆、经验池和代码哈希见 `manifest.json`。它是在查看上一轮 A/B 结果后提出的后续机制筛查，不是对原假设的盲目预注册，也不覆盖原主要检验。原 A/B 共3500次任务已全部完成。

## 为什么做这两项实验

旧 B 的 shuffle1 与 shuffle2 相差8个百分点。三个任务贡献净差值的62.5%；两组融合更新被跳过14与15次，总次数相近。旧 B 全部600次融合中，56次因规则超过100词被拒绝。我们检验更新接纳策略能否改变顺序差值，并单独检验一个有明确行为对应的规则案例。

不假设一定存在顺序效应，不以出现显著结果为停止条件。固定样本数，没有正式功效保证；小样本阴性结果不能证明机制不存在。

## 实验一：长度修复策略 × 融合顺序

| 因素 | 固定取值 |
|---|---|
| 经验池 | 原 B 已冻结的30组、83条经验；内容和哈希不变 |
| 顺序 | shuffle1、shuffle2；与原 B 相同的两个固定排列 |
| 策略 | 原策略 skip_baseline；新增 repair_length_once |
| 重复 | 每个策略×顺序组合独立生成3份最终记忆，共12份 |
| 测试 | 每份记忆在原20题上新执行一次，共240次任务 |
| 融合 | 每份30步，共360次原始融合提案 |

原策略使用原融合提示和验证器：不合规时保留上一步记忆。修复策略也先执行完全相同的融合，仅当提案因“规则超过100词”失败、且所有规则结构和来源都有效时，额外调用一次同模型缩短超长规则。输入只有超长规则的索引和正文；保留全部来源标签及所有未超长规则，要求保留原意、不增加建议，目标60–85词、硬上限100词。修复仍不合规则保留上一步记忆。每个提案最多一次修复；不因测试表现、文字不够理想或无改善而重抽。

修复最多额外360次请求，实际仅超长提案触发。此干预同时改变更新接纳率、额外计算和潜在规则语义；“通过格式验证”不等于语义完全不变。结果只解释为修复策略的效应，不能称为纯格式因果效应。

主要效应量预先指定为：

`(修复 shuffle1 − 修复 shuffle2) − (原策略 shuffle1 − 原策略 shuffle2)`。

每份记忆的20题平均成功率是一个统计样本，每格 n=3；不能把240次任务算作240份独立记忆。采用与原实验一致的独立组 Welch–Satterthwaite 线性对比、双侧检验和95%区间，四组原始分数全部报告。若样本方差全为零，不报告虚假的确定性 p 值或零宽区间。仅全部12份运行完成后计算主要检验。

四组均重新生成和执行，避免用新修复组直接对比旧基线造成时间混杂。运行调度以202609261打乱；该数字只是调度随机种子，不是模型生成种子。记忆生成和模型执行的随机性均包含在组内运行波动中。主要检验检验的是交互差值，不直接证明修复提高整体成绩，也不检验所有排列的方差。

## 实验二：固定规则删除消融

病例选择属于事后：旧数据贡献最大的三题中，192号旅行任务的失败理由与规则中的旅客验证要求明确对应。使用旧 `merge_shuffle2_r2` 的最终记忆，其原测试既有成功也有失败。后续一律新执行，旧结果不进入新检验。

固定 `multi_turn_base_192`，每次初始化相同模拟环境和新对话，三个条件各10次，共30次任务：

1. original：原完整记忆。
2. remove_rule：仅删除第9条（零起索引8），79词，要求订票前验证旅客等。
3. remove_control：仅删除第11条（零起索引10），77词的文件系统规则，作为近似等长的无关内容对照。

其他规则的内容与相对顺序全部不变。长度按空白分词计，不是 tokenizer 词元；无关规则删除也改变上下文位置，不能控制所有位置效应。目标规则还包含机场、实际价格和发票要求；整条删除的结果不能专门归因到“旅客验证”一句。这里只检验模拟环境中的任务行为，不推导真实支付或旅行场景的操作规则。

主要指标为官方完整任务成功率。预定两项比较：remove_rule−original、remove_rule−remove_control，分别用双侧 Fisher 精确检验，组内两项 Holm 校正。报告成功数/10、差值和保守95%区间：将两组各97.5%的 Clopper–Pearson 区间端点相减，由联合界保证每个差值区间至少95%的覆盖。它们不是多项比较的同时区间，也不一定与 Fisher 检验互为反演。

次要描述指标为第4个用户轮（订票请求当轮）是否调用 `book_flight`，另保存任意轮是否调用；不为该过程指标增加显著性检验。这里 n=10 表示同一记忆/同一题的新执行，不表示10种任务或10份独立生成记忆。调度随机种子202609262，不传未经验证的模型 seed。全部30次完成后才计算检验。

## 执行、缺失与停止

两项合计270次新任务、360次融合提案，以及按条件触发的一次长度修复。先完成规则消融，再执行融合实验，不根据前者成败取消或变更后者。两个实验各自的检验家族分开报告，不能据此声称总体多假设错误率统一受控。

模型和生成设置继承已冻结的校园配置：`DeepSeek-V4-Flash-0731-W8A8`，只访问校园端点；temperature=1.0、最大输出32768、请求 high thinking、每用户轮最多12次模型调用。两路并发、全局24次请求/分钟；服务端权重、采样和 high 语义无法完全审计。原 JSON 等价编码和客户端直连传输修复保持不变。

程序判分器可使用标准答案；执行模型只看到当轮及历史用户消息、工具定义/响应与相应记忆。修复模型不接收测试题、判分、标准调用或测试状态。20题已被研究者查看，本轮不是未见测试集的外部确认；不声称消除了所有数据选择偏差。

传输错误沿用已固定的同请求有限重试；基础设施中断不计为任务失败。完成的模型提案、任务与结果及时保存并在恢复时复用。格式失败计入方法表现，不按成功率排除。阶段最多三次从断点恢复；失败仍未解决时标记 needs_attention，保留所有已完成与失败记录，不填补成绩、不无限重试。进程在返回结果与落盘之间发生异常，仍可能造成服务端采样无法精确复用，完整日志用于披露这一限制。

只有两个实验计划的运行全部完成，状态才为 complete。运行期间不追加样本追逐显著性；任何后续改变另立版本。收到停止请求或发现 `results/mechanism_v1/STOP` / `results/STOP` 标记即停止并保留断点。

## 交付与复现

- `OFFLINE_AUDIT.md` / `offline_audit.json`：逐题贡献、跳过更新和三个案例的来源证据。
- `TEACHER_BRIEF.md`：可供老师阅读的一页进展汇报，完成后自动更新。
- `RESULTS.md` / `statistics.json`：新实验独立结果与推断边界。
- `STATUS.md` / `progress.json`：后台状态；详细轨迹保存在本地 `results/mechanism_v1/`。
- `mechanism.py` / `mechanism_pipeline.py` / `mechanism_report.py`：执行、恢复、统计。完成阶段后将报告同步至既有私有仓库；不将校园密钥、微信数据或个人文件纳入 Git。

首次冻结：`.venv/Scripts/python.exe mechanism.py prepare`（仅一次）。执行或恢复：`.venv/Scripts/python.exe mechanism_pipeline.py --workers 2`。重建报告：`.venv/Scripts/python.exe mechanism_report.py`，只读既有数据，不发模型请求。
