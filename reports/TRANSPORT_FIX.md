## 证据

- 小型请求及工具调用可成功；部分固定历史请求经代理约 0.03–0.05 秒返回无正文 503，直连则被重置连接。
- 同一请求移除某段正常任务记忆后成功，逐段测试复现第三段触发问题；这仅用于诊断，未将删减后的内容用于正式实验。
- UTF-8、缩小输出上限、移除思考模板、移除 reasoning 别名均未解决立即 503。
- HTTPS 同主机的 TLS 握手超时，未采用该路由。
- 使用标准 JSON Unicode 字符串转义并直连后，同一完整请求正常返回；有记忆和无记忆两条既有失败请求均已验证，详见 transport_validation.json。

证据支持 HTTP 传输路径上的内容匹配拦截/中间层兼容问题；没有网关或网络设备日志，不能确定具体拦截设备，也不能将所有历史 503/524 都归于这一原因。另有约 300 秒的 524，属于独立的上游超时现象。

## 修改

只在当前校园 API 客户端内选择直连，不修改 Windows 全局代理。将所有 JSON 字符串按标准 Unicode 转义传输，单元测试验证解码后键和值逐项一致，包含中文、emoji、换行、引号和嵌套工具参数。模型实际收到的提示、记忆、参数、工具定义不变。

524、连接中断及不完整响应纳入瞬态失败处理；最多三次请求重试，冷却 60/120/240 秒，尊重数值型 Retry-After（上限 600 秒）。401 等非瞬态错误不重试。阶段恢复间隔由 60 秒增至 300 秒，并保持每 15 秒检查 STOP。所有新请求记录传输版本、规范化请求哈希、时长及重试延迟。持续失败仍会在有限次数后停止，不无上限重试。

run.lock.json 只更新 gateway.py 的代码哈希，旧/新锁完整记录在 transport_amendment.json；实验 manifest 和任务断点签名不变。不重跑已完成结果，不混用诊断生成。继续使用校园 DeepSeek，付费官方 API 仍被阻断。
